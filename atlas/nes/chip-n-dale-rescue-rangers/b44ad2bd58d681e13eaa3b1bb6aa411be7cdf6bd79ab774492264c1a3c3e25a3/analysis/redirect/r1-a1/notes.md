## 4. Sanity check of the 0.8-confidence generic-data rule (coordinator concern)

Rule under review (pass 1): a 64-byte block is generic data when no linear decode run from any start reaches 48 bytes before an undefined opcode/BRK, no classified control-flow target lands inside, and nothing was fetched.

Checks (tools/lowrun_check.py, tools/island.py):
1. All Data regions in PRG04-15: searched for JSR/JMP abs whose target is an existing JSR target (known routine entry). Hits: 3; two are noise inside sprite-offset/tile tables (bank 1 / bank 5), one is real: fixed $FC43 `JSR YieldFrame` inside the region starting at $FC41.
2. Boundary scan: decode chains starting up to 40 bytes before each low-run region and ending in RTS/JMP/RTI inside it with >= 6 instructions and known-entry calls or >= 4 RAM operands. Only the $FC41 case ends inside a low-run region (two other chains, $90D4 bank 4 and $A3FA bank 2, are data that happens to decode; checked by hand).
3. Read-cluster Data regions (merged across <= 64-byte unread spans) in code banks: no chain crosses into or hides inside them.
4. Data banks 0/1 (PRG00-03) contain no code besides reset stubs: no fetch, no JSR target; holes there are tile-id arrays.

Conclusion: the rule's weak point is the region boundary (a routine tail spilling past a 64-byte block edge) and short (< 48 B) routines. One counterexample found and packaged (L-011, 8 bytes to move Data -> Code). No evidence that other low-run regions hide code; short unreferenced routines inside generic data cannot be excluded by this scan alone, but no candidate with known-entry calls was found. Confidence 0.8 is a reasonable label for those regions; no further reclassification proposed.
