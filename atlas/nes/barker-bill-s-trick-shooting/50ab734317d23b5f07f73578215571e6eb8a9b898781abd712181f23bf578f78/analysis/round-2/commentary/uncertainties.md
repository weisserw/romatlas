# Commentary uncertainties and redirect questions

Current-source readability is complete for the round-1 map. Unknown meaning is kept separate from unknown structural classification: 12,476 code bytes are explained, all 215 unknown intervals retain explicit boundary notes, and no byte was reclassified. Generic $FF data retains its accepted non-code status without claiming original padding intent. Final editorial acceptance is pending.

The current source uses mechanical scene/actor names where identity is uncertain. `work_XXXX` preserves storage identity for fields without a supported role. Scene-local aliases describe the demonstrated consumer and do not assert a universal object layout. Zero-page scratch and several actor fields are deliberately reused. ROM consumer aliases may point into structurally unknown intervals and do not establish complete table bounds.

1. **Inline dispatcher and adjacent words.** [Source](source/game.asm:8641), physical $0C53C..$0C552, consumes the JSR return address and jumps through A-th inline little-endian word; no table-return frame survives. Main dispatch [caller](source/game.asm:7796) has an unknown interval $0C0F5..$0C10B; CPU $C0F9/$C0FA are independently read as startup scene/round defaults (physical $0C109/$0C10A). Test whether the preceding twenty bytes form ten dispatch words using selector producers, endpoint constraints, target contracts and competing interpretations together. Do not require natural selection for static structure. Do not propagate an unresolved full-table claim to generic non-code subintervals. Repeat the same bounded analysis for the per-gallery inline tables, using each selector's finite domain and known continuation independently. This follows R01-L001; source comments intentionally do not expand classification.

2. **Metasprite and tileblock consumers.** [Metasprite source](source/game.asm:9510), physical $0CA6C..$0CAF8, proves a count-prefixed per-frame record containing Y offset, tile, attributes, X offset. [Tilemap source](source/game.asm:9630), classified through physical $0D849, uses 4x4 blocks and separate 64-byte attributes. Investigate their pointer tables and coherent record batches by independent endpoints and record/consumer consistency. Pointers alone do not prove code; a failure to recover exact asset grouping need not prevent generic data classification. Keep effective PRG bank context with aliases.

3. **Actor delay/frame streams and reel assets.** [Actor sequencer](source/game.asm:5523), physical $068EC..$06930, uses parallel delay/frame streams, with $FF wrapping delay cursor. [Reels](source/game.asm:7450), physical $0A60B onward, use three source streams, 24-position wrap and per-sprite masks. Investigate finite selector sets and neighboring stream layouts as connected consumer batches. Full original source organization and natural selection of every entry are not prerequisites; avoid extending a specific format past independently supported endpoints.

4. **Target/result fields and gallery identity.** [Input source](source/game.asm:8543), physical $0C4D8 onward, samples trigger bit 4 and produces a stable-edge event. Optical sensing/hit production remains untested because the toolkit has no Zapper interface (NES-001). Many hit/result paths are statically classified and fully described mechanically. Seek source-backed initialization/transition contracts to exercise Bills Thrills target throwing and distinguish per-gallery result flags. In particular, `$06F2` is round_number (HUD and capped increments); `$0625` is a separate auxiliary count, whose exact game meaning remains uncertain. Do not revive the rejected `$0625` round hypothesis. Reuse analysis/scenarios.json rather than replaying long startup.

5. **Audio streams.** [Interpreter](source/game.asm:10564), physical $0ED43 onward, has four channels, duration/note commands, counted loops and separate envelope/modulation tables. Remaining surrounding unknown bytes need bounded consumer and record-format work; nearby sound use alone does not classify them. `$4023/$4080/$408A` writes are preserved expansion-register accesses; their presence does not establish active FDS hardware on mapper 1. Exact sound identities, tuning and several special token semantics remain tentative.

6. **Scores and records.** [Comparison](source/game.asm:9448), physical $0CA23 onward, selects mode records at stride ten and compares a little-endian score capped at 9999. Retained CPU high RAM is signature/checksum-validated; battery is absent. Do not call this a battery save. Inspect record commit and secondary array consumers before giving fields stronger persistence/game names.

The baseline four-ISC $FF execution fragment at physical $0C004..$0C010 is retained as accepted observed code with exact directives. Its normal intended entry and purpose remain unresolved; it is not a basis for classifying adjacent $FF bytes as code.
