# Investigated meanings and limits

This pass reviewed all 9,950 classified code bytes, classified text/data/CHR blocks and the 260 unknown physical gaps against the frozen round01 map. Source comments explain known mechanics; they do not extend structural classification. The physical code fragments form 136 named mechanical units. Several units span raw gaps, and their explanations explicitly stop at missing continuations.

- Stage/password state is established by the compare consumer at physical 6700..6785: four-byte records produce selectors 1..15, stage index is selector & 7 and quest is selector & 8. $C8 is a started-game flag. The reset signature path can also set the quest flag to 1, so consumers treat it as nonzero, not exclusively 8.
- Inline transfer entries at CPU $D4B3/$D4B9/$D4BF pop and repair the JSR return address around a following pointer word. The word remains raw where the map has not classified it. Mode 2 reuses caller-prepared address/dimensions and takes a payload pointer; mode 1 repeats bytes; mode 0 reads the full descriptor. Linear source discovery must not cross those arguments as instructions.
- Metatile buffers, tile quadrants, attribute packing, queue producer/consumer cursors, OAM allocation direction and signed sprite coordinate clipping have mechanical explanations and symbols. Room record extents, full spawn/event command sets, room dimensions and natural selector domains remain redirect questions; pointer aliases do not prove tables beyond classified boundaries.
- Player screen/world coordinates, two player-shot slots, eight secondary slots and twelve parallel object slots are clear from their consumers. Original enemy names and several object parameter arrays remain address based. Temporary zero-page fields are shared scratch; names describe the reviewed consumer and are not global lifetime guarantees.
- The HUD converts a 16-bit value to five decimal digits and draws another two-digit field. Exact resource units, reactor/escape progression flags and some damage/recovery transitions remain unresolved. Source explains arithmetic and gates without naming them health, energy, a reactor timer or a particular enemy without sufficient support.
- The audio driver maintains ten logical channels, effect priority masks, note/envelope streams and separate software stack cursors. Command mechanics are explained where classified; isolated parameter readers do not prove missing command bodies. FDS register accesses are retained in this MMC1 cartridge build; no FDS device or expansion-audio compatibility is inferred.
- The source has fourteen direct control-flow operands into unclassified targets. They remain numeric and locally identified as unresolved target contracts. All other understood local/cross-slot entry aliases use recorded execution banks; a mapper register value is never called an effective bank index.
- Generic uniform blocks retain their original boundary evidence and unresolved semantic-format note. No padding/fill purpose is inferred from their byte pattern alone. CHR bitplane organization is known; individual tile scene assignments and palette choices remain runtime dependent.
- Runtime visits cover natural stage-one shooter plus artificial final-stage shooter/interior and both ending branches. No natural stage clear, core destruction or ending route is established. The source naming does not upgrade these reachability claims.

Concrete connected research continues from analysis/leads.json R01-L3..L6: room records/bounds, reactor/escape state, credit route and call/bank contracts. These uncertainties are explained current-source limits, not unreviewed readability ranges. Final whole-ROM editorial/archive acceptance remains pending, and 95,945 physical bytes remain structurally unknown.
