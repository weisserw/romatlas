# Investigated meanings and limits — final current source

All 163,856 physical bytes have evidence-backed structural roles: 24,862 Code, 104,266 Data, 1,960 Text and 32,768 Image bytes; zero bytes remain unknown. The 1,135 reviewed regions and 252 source-linked mechanical units cover the current source. Valid prior review was carried by physical range; complete prior commentary directories remain under analysis/round-02/ and analysis/round-03/. Remaining limits below concern semantics, natural reachability and hardware behavior, separately from structural classification.

- Stage/password selectors retain their established four-byte record interpretation: selector bits0..2 choose stage and bit3 chooses quest. The reset-signature path also sets quest nonzero; it is not exclusively the value eight. Exact resource units remain unnamed: current and limit are two 16-bit counters, ammunition is a separate decimal pair. Damage saturation and invulnerability gating are explained mechanically.
- Object arrays contain twelve parallel slots, secondary arrays eight and player shots two. The full 35 interior and31 shooter handler families now have mechanical explanations. ObjectState/Timer names deliberately remain generic because each type reuses these fields differently; enemy artwork names and original author intent remain unresolved. Shared zero-page scratch names describe consumer mechanics, not global lifetimes.
- All inline barriers are explicit. Fixed transfer helpers and bank-zero wrappers consume a two-byte pointer. $C62B reads count-prefixed four-byte coordinate alternatives and repairs the return while preserving carry. Shooter $9DD0 consumes its caller return, reads delay/count/type and returns to the OUTER caller. Secondary allocator $C77E returns normally on success but pops its caller return on exhaustion. These contracts must survive any port; ordinary local-return assumptions are wrong.
- Fixed continuation contexts distinguish physical backing from execution aliases: $CE8D after mapper3 has banks[6,7,14,15]; $CF05 after mapper1 has[2,3,14,15]; dynamic $C0C1 has[unknown,unknown,14,15]. The 25-page RAM copy may overcopy fixed code. Its runtime window is not evidence for a complete original table extent. Stage/map storage remains generic where packed/coordinate/palette patterns and consumer roles establish noncode without recovering individual schemas.
- Five bounded split-pointer/count containers have consumer-backed endpoints: title17, approach2, shooter72, interior115 and collision25. Independent endpoints and record lengths establish their bounds. Shooter collision arrays have19 entries for types12..30 with prebiased indexing, distinct from31 dispatch words. Player-state table has five actual words for states1..5; the prebiased origin is not a state-zero word.
- Story/credits streaming includes row-index skips at $1E/$3E; the scrolling text is not a simple unconditional alternating24/8 format. Congratulations continues after22*60 plus214*4 frames into actual STAFF credits. Prior600-frame stable observation was too short to imply terminal behavior. Reactor type$17 death raises progression and escape craft proximity selects escape; saved artificial core/escape/credits observations support these mechanics without a natural game-clear claim.
- Audio notes/envelopes, software stack control, register commands and wave upload mechanics are explained. Lookup/command-stream storage has multiple direct consumers, but individual stream extents and original generator layout remain unresolved. Retained FDS register writes do not establish an FDS peripheral or expansion-audio compatibility on this MMC1 cartridge.
- Small generic blocks were checked against direct references, neighboring barriers and repeated lookup/parameter formats in the independent review; an original schema is not invented. Uniform patterns do not establish padding purpose. CHR's two-bitplane organization is known, but tile-to-scene and palette assignments remain runtime-dependent.
