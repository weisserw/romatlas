## Physical $1C010..$1C016 / CPU $C000..$C006 / fixed bank14

Exact candidate: six Static Code bytes, `58 A9 FF 8D 07 80`, a CLI / load-FF / mapper-write prelude that falls through into independently accepted initialization at C006. Lower slot banks may vary; fixed slots are14/15. Narrow five-byte LDA/STA and one-byte CLI subclaims were also assessed.

The actual reset vector is C854, whose independently accepted SEI/JMP targets C006. IRQ vector C85C is RTI. Thus interrupt enable before resetting stack is possible under a supported quiet-PPU/IRQ precondition, not an opcode-level contradiction. No actual caller is demanded. None of these observations proves the prefix is data.

Independent revised method: evaluate the proposed bank7 initialization against ROM bytes at CPU8007 in every possible lower pair. Raw values are02,02,03,30,98,82,20,A2; their low3bits are2,2,3,0,0,2,0,2. Under bus-conflict masking, FF cannot force7 from these bytes. The known FEFD mapper setter instead writes matching bytes through independent fixed FF0C..FF13 values0..7. This falsifies **deterministic conflict-safe bank7 initialization** only. It does not falsify prefix code, and a general hardware-write prelude does not require deterministic bank7: C006 stays mapped and pair6 is selected later. No undocumented emulator bus-conflict behavior is inferred.

Strongest competitor: a short uninterpreted retained byte block immediately before independently anchored initialization. It has no positive data pattern, so Generic Data is not justified. Equally, the prefix has no relocated branch, independently consumed inline record, supported input-to-output transformation beyond the single decoded hardware store, repeated helper layout, or encoded C000 origin to discriminate its role. Combining the bank edge and following reset strengthens plausibility but still supplies adjacency plus legal meaningful decoding, rather than an independent structural discriminator. The CLI one-byte claim is weaker; the five-byte claim retains the same limitation. There is no counterexample disproving code, just insufficient support for choosing it over unknown content. The missing actual caller is not the decisive premise.

Concrete test considered and closed: all-bank8007 constraint above; outcome reduces the strongest *specific* mapper-initialization interpretation but leaves generic prelude unresolved. Arbitrary PC execution would demonstrate these already-known mechanics only. An independent encoded entry/origin, analogous multi-instruction boot stub tied to this layout, or consumer identifying these bytes would change the assessment; none is identified in current evidence. Repeating gameplay or scanning the same pointer domain does not supply that fact.

The comparison does not turn absence of an incoming branch into data evidence.
