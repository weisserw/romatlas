1. **All three bytes Static Code from CD25.** Decode is LDY #1 at CD25, ISC $00A9,X at CD27 (three bytes, consumes the independent CD28 LDA #0 bytes), then TAX at CD2A and accepted actor fill loops. Thus the prior phrase 'unfinished unofficial instruction' describes the unknown interval, not an invalid instruction or bank truncation. This is a genuine legal overlapping stream. ISC increments RAM at $00A9+X (with RAM aliases), subtracts that incremented value and incoming borrow from A; TAX uses the result to select the first page's starting position. The first page loop writes initial X down through1 if initial X is nonzero, or all256 entries if initial X=0; it ends X=0. The second fills all256 entries. Thus A=0 also makes TAX set X=0 and recovers the complete accepted clearing loop. Actor-count/history writes retain A, and the existing consumer then selects CHR using LevelSelector. A suitable A/X/carry/memory precondition can produce A=0 and preserve clearing semantics; consequently this stream is not falsified universally. But no independent local constraint selects the read/modify/write, entry X or arithmetic precondition, and LDY1's useful effect is only a hypothetical returned Y. Accepted CD28 establishes precisely the zero-fill contract without any such extra behavior. Valid decoding plus a manufactured precondition therefore does not establish the proposed earlier entry. No accepted instruction starts FF anywhere in the current map (a style constraint, not a prohibition or standalone disproof).

2. **A001 only Static Code, FF generic Data.** LDY1 alone neither terminates nor branches. It would fall into FF, so this split lacks a supported control/inline-data consumer that could skip the data. The established CD14 JMP at CD22 ends atCD25 and does not supply that skip. A standalone two-byte abandoned fragment is possible but 'abandoned' would be an unsupported historical claim. Reject only this isolated code/data split, not all static unreferenced prefixes.

3. **01FF code at CD26, A0 data at CD25.** This corrected narrower alternative uses entirely official opcodes: ORA ($FF,X), then CD28 LDA0. The LDA destroys A and N/Z effects; ORA leaves Y/X/carry unchanged, so absent externally meaningful read side effects the prefix contributes nothing to the accepted routine. Its indexed-indirect read can target RAM/IO/ROM depending on an unconstrained pointer. A purposeful read side effect is possible, but there is no independent read target/entry contract to distinguish it from accidental decoding. This test rules out the assertion that every code alternative requires unofficial opcodes; it does not prove this alternative is code or data.

4. **FF alone code at CD27; A001 data.** Same legal overlapping ISC stream as(1), without the hypothetical Y return. It still requires independently unsupported arithmetic/read-modify-write intent and precondition. The crossing of CD28 is not itself a contradiction: overlapping views can exist. No proposal based solely on exclusion of overlap is made.

5. **All three generic Data, or proper subintervals thereof.** Neighbor boundaries independently locate a three-byte hole between a tail-returning wrapper and independent actor-clear entry. They rule out ordinary preceding fallthrough; they do not establish noncode. A001FF occurs only once in PRG. A0/01/FF can be parameters plus terminator, a word plus tag, stale instructions, or another unreferenced object. There is no repeated/uniform run, visible tile/text/record encoding, nearby indexed consumer, or bounded inline-data contract connecting it to the stage-card tile data before CD14 or CHR pairs after CD58. The isolated final FF is not a uniform suffix: its one-byte length and possible ISC entry give no patterned-data discrimination. The two-byte A001 prefix is as plausible as LDY1 as a small datum. Generic data does not require semantics, schema, original generator, or known consumer; here the obstacle is specifically insufficient noncode evidence, not unknown meaning. Arbitrary three-byte brevity does not establish any role.
