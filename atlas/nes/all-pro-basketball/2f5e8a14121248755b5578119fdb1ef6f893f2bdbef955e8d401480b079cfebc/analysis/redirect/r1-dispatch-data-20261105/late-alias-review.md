# Localized late-copy review

Physical [0x177C9,0x17FE0) equals [0x1F7C9,0x1FFE0) byte for byte. The preceding44 bytes [0x1779D,0x177C9) differ at all44 positions: the PRG15 copy contains repeated small encoded fields and FA terminator, while PRG11 contains menu code. This observation rejects a whole-fragment duplicate-code transfer, not every later subinterval.

A lower-window execution view for bank15 can be stated as effective [14,15,14,15], with CPU $Bxxx resolving physical $1Fxxx. This is a supported MMC1 static context, not evidence the game selects it. However, matching instruction bytes alone do not settle the role of the entire late fragment. Some menu branches refer back into the differing prefix; password decoding also depends on the $B53C substitution table, which is not copied into this alias. Propagating the original entire call/data graph under a renamed bank context would therefore be unsound. This is a concrete dependency mismatch, not a requirement for natural selection/caller evidence.

Narrow supported code proposal: four copied routines with independently closed mechanical contracts and no external ROM dependencies: CPU $B834..B848 performs quotient/remainder of RAM stage by7; $B848..B852 clears seven RAM record fields; $BD5A..BD6D maps12 RAM nibble-like fields to bounded ASCII via addition/modulo26; $BE0F..BE2F implements RAM-held input repeat countdown. Known source bodies, loops/branches and returns are identical; no mapper write, external call, ROM lookup or stack manipulation is present. Their exact original physical source ranges are in package.py; corresponding +$8000 targets total81 bytes, Static provenance, views [14,15,14,15] at original CPU B addresses. These claims do not require a caller but do require the stated bank context.

Non-code pattern slices in the exact matched suffix transfer independently as Data; paired FF-rich tails, numeric directories, palette/roster/tile strings do not become ambiguous merely because other copied bytes are executable-form fragments. Main unmatched44-byte prefix is separately supported as generic repeated encoded data. Remaining late executable fragments stay unknown where their role/context/dependency contracts have not been established. Do not classify them generic solely because no fetch was observed, and do not reject the narrow pure-RAM functions because the earlier prefix differs.

Primary artifacts: input/game.nes; data-review-bytes.txt/data-review.json for source/target pattern inspection; all-bank10-scenes-graph.json and password-decode-{b834,bd32,be2f}.json for original routines; runtime-fetched-code.json (no observed late B alias claimed); proposal.json exact views/bounds. Reproducible byte comparison and narrow transfer are in package.py.
