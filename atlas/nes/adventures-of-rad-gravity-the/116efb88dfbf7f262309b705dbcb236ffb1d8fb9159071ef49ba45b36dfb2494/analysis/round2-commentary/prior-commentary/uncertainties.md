# Round 1 unresolved meanings

Current classified-source readability is complete. These are interpretation/classification limits, not skipped source ranges. Source comments explain the demonstrated mechanics and preserve uncertainty locally. Final editorial acceptance remains pending.

- Physical ROM complement: 94,946 bytes remain unknown. Exact intervals are in analysis/round1/unknown.json and every emitted unknown interval is noted in commentary/source/game.asm. Nearby code, pointer values and successful rebuilding do not classify those bytes.
- Asset resolver CPU $C77C, physical [0x1C78C,0x1C7B8): selector bits choose a PRG bank, whose CPU $8000 header points to a base. A masked two-byte relative-pointer entry is added to that base. Exact bank/table extents, asset headers and all consumer formats remain open. DecodeAssetToVram skips four header bytes and uses packed output, but this does not establish every asset's format or physical extent.
- Packed decoder: bit-reservoir, lookup/recursive-node mechanics are explained. Its original compressor/tool identity, intended asset classes and all encoded input limits are unknown. RAM $0300/$0400 tables overlap password/display workspace by mode. Decoder output at $0700 also overlaps object animation arrays. Shared names describe demonstrated uses, not exclusive ownership.
- Object coordinates: $0748/$0754 are left/right bounds; $0730/$073C are top/bottom bounds. Their fractional state and conversion to OAM are documented, but a universal pixel/world unit is not asserted. The allocator uses 12 object slots while stage initialization clears 16 array entries; do not silently assume the larger clear loop is the allocation limit.
- Health/damage: $0790[X] is health and $06C4[Y] contact damage. The player is slot 0, with $0088 damage cooldown and $000A difficulty shift. Nonplayer health reaching zero affects a sound choice; the script interpreter tests zero health. Boss slot identity, vulnerable phase, defeat script and ending transition require inspection of the existing boss-engaged snapshot. No boss defeat, second-boss visit or ending is claimed.
- Inventory/icon mechanics and item-flag consumers are named, but complete weapon/icon/game-item identities remain unresolved. Stage selectors are numerical contracts; only previously recorded gameplay associations are established.
- Object/script interpreter: operand, branch, movement, timer, packed-bit, contact and text mechanisms are explained where classified. Unmapped opcode-table entries/handlers remain unknown. A single shared script return pointer does not establish support for nested script calls. Script pointer advancement contains an alternate LDA entry inside a BIT operand; the original overlapping bytes and exact control targets are preserved.
- Physical [0x1EA23,0x1EA2C), CPU $EA13 onward, is an observed arithmetic loop that writes PPUMASK. Its ordinary game/error/debug purpose is unresolved. It is described as a loop rather than invented as a normal gameplay handler.
- Audio streams: pitch, sequence, delay, envelope, modulation, ownership and hardware writes are explained; sound/music identities and original tuning are unknown. The statically supported PlayPCM contract does not establish a natural caller. Its consumer-supported PCM interval is exact; adjacent generic data is not assigned an invented original sample/fill purpose.

Local consumer explanations remain meaningful; the symbols deliberately retain addresses instead of inventing semantics.
