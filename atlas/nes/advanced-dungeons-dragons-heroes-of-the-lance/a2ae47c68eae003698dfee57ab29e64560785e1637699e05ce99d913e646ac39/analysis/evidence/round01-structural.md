# Round 1 structural decisions

Physical offsets include 16-byte iNES header. Layout and mapper validated by inspect and baseline verification. CHR [0x20010,0x40010) is Image: dedicated PPU 2bpp pattern storage declared by header, separate from CPU PRG. Header [0,16) is Data.

Final vectors [0x2000A,0x20010) encode C06B/C000/C063. Reset C000 starts SEI/CLD, resets MMC1 through INC $E997, jumps C01C, initializes stack/PPU and calls fixed-bank helpers. NMI/IRQ code and observed roots establish vector entry contexts. Earlier 16 KiB bank ends repeat C06B/C000/C068 vector-shaped six-byte records, independently bounded by bank boundary and repeated long FF tails; Data role asserted, no execution/reachability claim for them.

Code annotations derive accepted contextual instruction fetches (Observed) and direct static control flow (Static). Candidates were inspected for physical overlap (none); contiguous slices are merged only when context, linear CPU alias and provenance agree. Observed instruction start implies its decoded operand extent; no next-PC-only coverage. Static discovery stops at unresolved mapper-affecting operations/calls; direct callee entry preserves pre-call banks and can be seeded explicitly, without assuming the post-return context. Indirect JMP targets remain unknown. Three diagnostic physical sites in the original sample plus one later site are unresolved dispatch questions; see discovery-diagnostics.json.

Uniform non-code candidates were bounded to exact byte transitions, checked against code and direct references, with surrounding bytes retained in uniform-boundaries.txt. All had zero direct reference hits and no code conflict. Bank-tail FF runs, internal FF separators and bounded zero run are Data, not Padding: their specific generator/fill purpose is not established. Nearby bytes include repeated tile/record patterns, terminal RTS sequences and the bank-end vector records; no instruction continuation enters the accepted uniform runs. Zero run at 0x4FA0..0x4FEC lies amid repeated sparse record data; its meaning remains unresolved. This bounded inspection supports code-versus-data only; surrounding unsolved intervals remain Unknown.

Readable source is generated/pass-001/game.asm; commentary is a separate next phase. Baseline raw fallback was never imported as classification. No code/data decision follows solely from successful rebuilding or absence of gameplay coverage.
